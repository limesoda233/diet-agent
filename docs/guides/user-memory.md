# 用户长期记忆

本功能只使用 MySQL。当前阶段覆盖用户档案、原文证据、消息驱动任务、跨会话默认偏好及记忆管理；不新增向量检索，不涉及多智能体规划。

## 启用

1. 在现有 `diet_db` 执行 `src/main/resources/db/migrations/005_user_memory.sql`。该脚本只新增 `user_memory*` 表，可重复执行，不修改现有消息/餐食数据。不要重新执行含重建表的 `diet_db.sql`。
2. 在 IDEA 应用运行配置的环境变量（或该配置选择的 `.env` 文件）增加：

```dotenv
USER_MEMORY_ENABLED=true
# 普通LLM基线需要现有 DEEPSEEK_API_KEY；密钥仍放本地环境，不写代码。
# 可选的Jev分类增强；未完成本领域真实评测，默认false。
USER_MEMORY_JEV_ENABLED=false
```

3. 重启 Java 应用。现有前端开发服务会加载源码；单服务部署先执行 `npm --prefix frontend run build`，再启动后端。导航中的“饮食记忆”管理本人记忆。

应用不会自动加载任意 `.env`，须沿用已经配置好的 IDEA Environment variables 文件。后台任务从 MySQL 领取；不需要启动 Redis、消息队列或新增向量库。默认全局关闭，以免未迁移的已有数据库阻断聊天。

## 行为

- “我平时喜欢清淡”：自动保存本人明确长期偏好，回复独立提示可修改或撤销。
- “今天我想吃辣”：本轮偏好，不直接成为永久档案；跨多个独立会话的明确口味证据可能归纳成软偏好。
- “我对花生过敏”：本轮立即生效；长期条目为待确认，可在页面确认、编辑或撤销。待确认期间后续请求仍保守处理这条过敏声明。
- “我妈喜欢辣”：不能写成本人口味；假设、引用及否定过敏不作为肯定事实。
- “以后不吃香菜”：本人明确长期禁忌；与本轮必须食材冲突时澄清。当前食材词表不认识的忌口不会被静默忽略。
- “忘记我喜欢清淡”：明确撤销普通偏好；过敏档案只能通过管理页面明确确认修改/撤销。
- 关闭收集停止新增持久任务及证据，不删除已有记忆。当前输入仍会被解析以服务本轮请求；已有约束继续生效，需另行撤销。

管理页支持列表、确认、编辑、撤销与收集开关。编辑携带版本号；并发更新或旧页面操作被拒绝后重新加载。沿用项目练习环境的 `X-User-Id`，这是用户隔离标识，不是生产认证。

## 写入和后台任务

消息与 `user_memory_job` 在一个数据库事务内保存。模型调用在事务外，在线等待本轮条件解析后才进入规则/模型路由；成功后复用同一抽取结果完成写入，不再额外调用一次模型。失败任务由后台处理，推荐失败不删除已提交的用户声明。

后台默认每5秒领取最多10个任务；领取有60秒租约，最多5次尝试，失败30秒后再试。任务持有用户档案epoch，编辑、撤销和收集开关改变epoch，过时任务失效；单事实还检查来源任务顺序。修正可能使其他较早排队的声明失效，这是避免旧事实恢复的保守取舍。用户可以通过新声明重新提供普通偏好；重新声明过敏仍需确认。

`user_memory_evidence` 按消息任务/事实去重。每小时对近30天的口味/菜系证据按独立会话归纳，默认至少3个会话；该门槛是可配置的初始工程值，未经真实偏好质量校准。INFERRED记忆有效期30天，只给排序小幅加减分，不进入SQL召回默认槽位、不覆盖EXPLICIT、不推断过敏。

`user_memory_exposure` 记录实际展示；反馈可携带 `traceId`，只有与用户、会话、餐食共同匹配展示记录时，才写入 `user_memory_feedback`。重复反馈幂等更新。首版保留这些反馈证据供追溯，不把“喜欢整道菜”推成喜欢全部配料；当前自动归纳仅使用用户消息中的明确口味证据。

## 检索和边界

本人明确偏好在该维度没有本轮/会话值时填默认值；“清淡”映射现有healthGoal。推断偏好与不喜欢的口味仅用于软排序。本轮明确值优先；长期忌口在MySQL食材过滤与菜谱查询约束中叠加。服务器抽取的临时排除条件也传到餐食、多餐规划、显式菜谱和模型兜底菜谱，不写入长期档案；新增的临时排除元数据不保存进会话状态。

当前库没有完整过敏原、复合调料及交叉接触证明：存在本人过敏声明或有效/待确认过敏档案时，保守停止推荐、做法和视频输出并说明证据不足。不能将“主食材未列出花生”当作“适合花生过敏者”。忌口视频也缺乏配料校验，纯视频请求拒绝，混合请求只走文字菜谱。

厨具和分钟限制可记录/编辑，但现有餐食与公共菜谱缺乏可完整验证的时长/工具元数据，因此首版不据此保证过滤达标，回复会显示缺口提示。记忆存储不可用时不继续声称结果满足个人限制。

## 提取与配置

DeepSeek是开放事实的无状态结构化提取基线。每项返回type/value/subject/stance/scope/operation/evidence；必须有原文证据，拒绝非法/缺失字段和尾随数据。Jev启用后只增强固定词表中的TASTE/CUISINE主体、态度与期限分类；它运行在基线候选之后，**不是跳过DeepSeek的快速路径**。低置信、缺失或异常回退已校验基线，不能宣称降低了模型调用次数。

可在 `application.yml` 配置：`diet.memory.extraction-timeout`（8s）、`jev-confidence-threshold`（0.85，独立于意图阈值）、`jev-timeout`（3s）、`worker-delay-ms`、`worker-initial-delay-ms`、`consolidation-delay-ms`、`inference-min-sessions`。这些默认值不代表已完成概率校准。

Trace只记录 `MEMORY_PREPARED` 的候选/记忆数量和状态，持久档案与证据按userId保存；敏感记忆不放公共索引。已有调试Trace可能包含原始用户请求，生产使用须配套真正的身份认证和日志访问控制。

## 验证

```powershell
mvn test
mvn -DskipTests package
npm --prefix frontend test
npm --prefix frontend run build
```

普通测试通过H2/MySQL模式和受控模型验证事务、重试、用户隔离与路由；不连接真实数据库，不自动调用远程模型。14条固定开发样本及显式真实提取评测见 `src/test/resources/evaluation/memory/README.md`。开发样本是助手编写并手工指定预期的诊断数据，未经用户独立复核，也不是锁定测试集。真实提取准确率、误写率和Jev收益仍待显式评测。

API：`GET /api/v1/diet/memories`；`PUT /memories/settings`，body为`{"collectionEnabled":false}`；`PATCH /memories/{id}`，body含`version`、`action`（CONFIRM/UPDATE/DELETE），UPDATE还需`value`、`stance`。不能从请求体指定另一用户。
