# 001 餐食检索评测规格

状态：已实现并通过工程验收；相关性标注仍为 draft。日期：2026-09-10。证据见 [acceptance.md](acceptance.md)。

## 目标与边界

当前七维 JSON_OVERLAPS 检索在非空维度间使用 AND，按更新时间截取最多 50 条；MealRankService 排除历史推荐并按标签重叠排序，生成服务消费前三名。现有意图数据集和 Trace 评估不能直接衡量餐食召回、排序质量。

本阶段建立可复现、可诊断的离线基线，不改变线上检索、排序、Prompt 或 API，不要求现有算法达到人为设定的高分。不接入 embedding、Qdrant 或 MCP。

## 数据契约

1. 冻结仓库 45 道种子餐食：diet_db.sql 中 5 道，add_40_meal_items.sql 中 40 道。固定评测 ID、时间戳，记录源文件、名称、数据域、所有者及七维标签。ID 不宣称对应实际数据库自动分配的 ID。
2. 补充主要食材、简短做法与描述，标记为 `synthetic_recipe_assumption`。这些是假设配方，不写回生产，也不作为营养或完整过敏原证据。保留原始标签，不把有疑问的健康标签改成已核验事实。
3. 至少 64 条查询，覆盖直接标签、口语改写、多偏好、禁用食材、已有食材、换一批、数据隔离、无匹配。每条含 id、groupId、split、slice、utterance、context、sourceMode、userId、slots、excludeMealIds、excludedIngredients、requiredIngredients、relevanceGrades、rationale、annotationStatus。
4. 初稿标注者为 assistant，状态为 draft。用户复核后才能标记 reviewed。相关性不可由现有检索器的返回结果反推。
5. 对查询数据域内全部餐食标注 0/1/2（不相关/可接受/优先推荐），以保证 Recall 分母与理想排序可计算。明确记录判定理由。禁止把未标注条目静默当作负例。
6. 同一需求的近义改写共用 groupId，组不能跨 dev/test。数据校验检查引用、重复 ID、完整标注和分组隔离。
7. sourceMode/ownerUserId 为数据边界；excludeMealIds 为换一批限制。食材约束以规范化食材 ID 和固定假设配方为判断依据。“家里有这些”不自动等价为“只能使用这些”。
8. 当前算法不支持食材约束，挑战样本仍运行，并明确记录 capabilityGaps 与违规，不能剔除困难样本以抬高成绩。
9. 显式 ingredientVocabulary 包括实际主要食材与合法但当前没有菜品的食材；禁止从查询拼写自动扩充词表。拒绝未知 ID、前后空格、小数等级/ID、字符串等级和重复 JSON 属性。组级 annotationStatus 在生成时保留。

## 运行契约

- 默认 `mvn test` 不依赖数据库、网络或 API Key，运行指标、数据契约和报告测试。
- 真实 MySQL 基线通过显式开关运行，使用独立评测实例和专用环境变量，不读取 application.yml 的业务数据库连接。
- 在独立 JDBC 连接中创建临时 meal_item 表、加载快照，MyBatis 同会话读取；关闭连接后临时表消失。不运行仓库建库脚本、不 DROP 业务表、不修改真实餐食。
- 直接加载生产 Mapper XML，复用 MealMapper → MealService → MealSearchService → MealRankService；不复制一份 Java 版 JSON_OVERLAPS 冒充 MySQL 基线。
- 固定槽位轨道直接传入样本槽位，原始查询保留给后续混合检索。真实 LLM 端到端轨道留到后续阶段，分开报告槽位识别和检索表现。
- SQL 或连接失败必须令评测失败，不回退到内存模拟，不产出成功报告。
- 预热一次后重复采样，记录次数和 P50/P95。此耗时仅包含本地检索、排序，不包含 LLM 或 embedding。并列更新时间导致的顺序波动如实记录，不修改生产 tie-break。

## 指标契约

相关定义为 grade > 0。相关集为空的样本单独评估无匹配能力，不把其 Recall 设为 1。

| 指标 | 口径 |
| --- | --- |
| 候选 Recall@50 | 候选命中相关数 / 数据域内全部相关数 |
| 最终 Recall@3 | 前三名命中相关数 / 全部相关数 |
| Precision@3 | 前三名相关数 / 3；不足 3 条仍以 3 为分母 |
| nDCG@3 | gain=2^grade-1，discount=log2(rank+1)；理想排序来自完整标注；IDCG=0 时为 null |
| MRR@3 | 前三名首个相关条目名次倒数；有相关但未命中为 0 |
| 约束违规 | 数据域泄漏、已排除 ID、禁用食材、缺少必需食材分别计数；记录违规结果数、受影响查询数和各自分母 |
| 无匹配正确率 | 仅在无相关样本上判断是否返回空结果 |
| 空结果/不足率 | 在有相关样本上报告；区分可用相关项本来不足与检索漏召回 |

另记录 corpusLimitedQueries（相关项只有 1～2 道）与 shortReturnQueries（实际返回少于 3 条，含无匹配），避免单一不足率掩盖语料规模限制。

普通相关性指标对无相关集返回 null，聚合跳过并报告有效分母。重复/未知返回 ID 记为执行契约错误，不能去重后悄悄提高成绩。约束违规在原始结果上计算，禁止先删除违规项再打分。按 split、slice、annotationStatus 分组；质量、耗时、能力缺口分开，不合成总分。

## 报告契约

输出 `target/evaluation/retrieval/` 下 Markdown 汇总和 JSON 明细。记录语料/查询 SHA-256、策略名、Git HEAD 与 dirty 标记、Mapper XML SHA-256、JVM/MySQL 版本、运行时间、预热与重复次数、评价口径版本。

每条记录保留原话、固定槽位、候选 ID、Top3、分数、指标、违规、能力缺口、相关性理由与标注状态。禁止写入数据库密码、API Key 或带凭据连接 URL；JSON 不含 NaN/Infinity。

dev/test 分别标识。第二阶段参数冻结后才运行 test。合成配方给未来检索器带来的额外信息与算法差异必须在比较报告里注明，不能把全部提升归因于 embedding。

## 限制与变更记录

- 45 道餐食和助手草拟标签只构成工程基线，不外推为真实用户效果；后续需要用户复核和真实请求扩充。
- 45 道数据不足以暴露 50 条截断；单独增加超过 50 条的隔离诊断场景，不混入质量数据集。
- 原始标签与假设配方未经真实营养/过敏原核验。
- 2026-09-10：依据用户选择形成初稿；用户确认“按此规格开始实现”。
- 2026-09-10：独立审查补充食材词表、严格整数/重复属性校验与不足结果的分项统计，不改变产品范围。
