# 014 用户长期记忆

已确认设计（2026-10-20）：MySQL 是唯一权威存储，不增加 embedding、向量记忆或多智能体规划。

## 行为契约

- 记忆类型：ALLERGEN、AVOID_INGREDIENT、TASTE、CUISINE、EQUIPMENT、MAX_MINUTES。本人明确长期普通偏好自动保存，可撤销；过敏声明本轮生效，长期状态为 PENDING，确认后 ACTIVE。
- 用户消息是证据，Trace 仅关联审计。SELF、肯定事实、原文证据及作用范围必须校验；他人、假设、否定事实、模型输出不形成个人事实。TEMPORARY 不写长期档案。
- 消息与记忆任务同事务提交，Worker 不依赖请求成功或 Trace 落库。任务具有领取租约、重试上限、幂等、失效旧任务保护。模型调用不占数据库事务。
- 在线抽取先于所有推荐/菜谱/视频分支。抽取失败且涉及禁忌时澄清；不声称未成功保存的记忆已保存。关闭收集不删除已确认记忆，用户可另行删除。
- MySQL 生效记录按 userId 查询；普通偏好是默认值，不覆盖本轮明确要求。过敏及禁忌是硬限制，不得被本轮模型槽位抹去。
- 当前餐食/公共菜谱没有可核验完整过敏原元数据，存在过敏声明时保守提示并停止提供“适合过敏用户”的餐食/做法/视频；不把主要食材列表当安全证明。
- 厨具与时长只在有可核验元数据的路径施加；无法核对的场景告知缺口，不伪造约束满足。新会话读取有效档案；删除/修改后旧任务不能复活旧事实。
- DeepSeek 提取开放事实，Jev 是可选的基线候选之后的固定词表态度/主体/范围分类增强，不是跳过基线的快速路径；统一 MemoryCandidate 接口。未配置/失败不静默视为无记忆。独立阈值，拒绝不完整回答。无远程质量提升宣称。
- 后台按独立会话聚合明确长期/临时口味证据，推断仅用于软排序，不能覆盖已确认记录、推断过敏或以系统曝光充当用户选择。
- 记忆管理 API/页面：列表、确认、修改、删除、收集开关。沿用练习环境 X-User-Id，明确不是认证；所有 SQL 与操作限定 userId。

## 验收

覆盖跨会话、他人/假设/临时/否定、多事实、过敏确认、未知食材、提取失败、关闭收集、删除水位、重复任务、租约重试、过期、并发版本、用户隔离、快捷路由、Jev 降级。普通测试使用受控模型与 H2，固定数据集不依赖真实 API。真实模型评测显式启用，报告覆盖率、误写率、字段准确率与延迟。
