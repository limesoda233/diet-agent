# React 前端重写

状态：用户已确认，工程验收完成，见 [验收记录](acceptance.md)。用户要求全部重写前端，改用 React，并修复聊天输入框不固定、回车无法发送等交互问题。

## 范围与技术

在 `frontend/` 建立 React + TypeScript + Vite 工程。采用 React Router 的 hash 路由以兼容 Spring Boot 静态部署与旧书签；集中封装类型化 API、用户身份、异步请求和错误处理。按功能拆分聊天、餐食、Trace、评测模块，使用局部状态与 Context，不引入全局 Redux 或新业务后端。

重写全部现有页面：首页、聊天、个人餐食、公共餐食、Trace 列表/详情/标注、意图评测。保留原 `/api/v1/diet` 接口及 `X-User-Id` 契约。当前用户编号是练习项目的身份切换能力，界面不把它包装成真实登录认证。

不改变 MySQL 推荐、公共菜谱 RAG、MCP、后端草稿事务或评测数据。旧原生 JS/CSS 与其替身测试在功能迁移及对应测试完成后退役，移除旧入口，避免两套前端并存。后端测试仍完整执行。

## 视觉与导航

默认打开聊天，桌面使用固定宽度的深绿侧栏、白色内容区和浅灰绿色背景。主色 `#176B52`，侧栏 `#143D32`，正文 `#17382E`，背景 `#F3F7F5`，边框 `#DCE7E1`，强调色 `#D28A31`。CSS 变量统一颜色、间距与圆角。

中文标题使用系统黑体中偏重字重，正文系统无衬线，Trace/代码使用等宽字体；字体依赖本机回退，不要求外部字体网络请求。主标题不超过 28px，正文 15–16px，菜谱标题保持清晰但不占满屏。用食材标签与分段步骤形成料理相关的视觉识别，不增加装饰性统计卡或大渐变。

桌面导航分为“饮食助手”和“调试工具”，餐食管理使用搜索列表与编辑区；Trace 使用列表与详情。手机侧栏折叠为可关闭导航，单列内容，表格可横向滚动。键盘焦点可见，表单关联标签，错误提示就近展示，按钮有加载状态。

## 聊天

- 外壳占满动态视口高度；头部与底部输入区保持可见，只有消息列表滚动。手机考虑安全区和软键盘，输入区不得遮挡最后一条消息。
- Enter 发送，Shift+Enter 换行；中文输入法正在组合文字时 Enter 不发送；空白消息不发送。
- 输入框自动增高到设定上限，超过后内部滚动；请求期间禁止重复提交，失败保留输入并可重试。
- 新消息在用户接近底部时自动滚动；用户正在查看历史时不强制拉到底，显示“回到最新”。
- 保留个人/公共数据源、当前会话、新对话、推荐卡、三餐计划、反馈、菜谱 Markdown、本轮引用、教学视频卡、餐食草稿与确认/取消功能。
- Markdown 使用 React 渲染组件，禁用原始 HTML；链接协议校验。视频链接保留 Bilibili 域名限制及新窗口安全属性。
- 草稿动作只对当前用户/会话/最新草稿版本生效；文字确认及按钮确认保存后刷新餐食缓存。切换用户或新对话时取消或丢弃旧异步响应。

## 餐食与调试页面

个人餐食：搜索、标签展示、新增、编辑、删除确认、一句话整理、可编辑知识、必填校验、防重和失败恢复。生成草稿只预览；新增保存知识，编辑未改知识保留来源，明确编辑后使用 USER_PROVIDED。

公共餐食：只读列表、搜索及标签筛选，不展示个人编辑操作。推荐继续依赖后端 MySQL。

Trace：时间/会话/未标注筛选、列表、事件时间线、可展开输入输出、JSON 格式化、标签表单。意图评测：时间范围、数量、可选 LLM judge、指标及明细；明确区分此页面与离线 Ragas，不新增线上 Ragas 执行接口。

## 构建与运行

开发：`frontend` 下安装依赖并运行 Vite，代理 `/api` 到 Spring Boot；Java 与前端分别启动。

本地单服务/IDE：构建命令将 React 产物生成到 Spring Boot 静态资源目录，然后启动 Java，继续使用一个后端地址。静态产物、node_modules、测试报告和缓存忽略；提交 React 源码、package.json 和 lockfile。增加可选 Maven 前端构建 profile，确保干净检出可通过明确命令打包包含前端的 JAR，后端单元测试无需安装前端依赖。具体命令写入 README 和运行指南。

## 验收

1. React 覆盖全部旧页面与 API 功能，无旧原生脚本入口。
2. 长聊天滚动时输入区保持可见；Enter、Shift+Enter、中文组合输入、重复提交及失败重试有真实组件交互测试。
3. Markdown、引用、视频、推荐反馈、草稿保存及知识编辑回归通过。
4. 换用户、新对话、重新生成、取消操作不会接受旧请求或执行旧卡片。
5. 桌面和手机受控浏览器走查，检查布局、输入区、主要表单与调试页；受控接口结果不宣称真实模型质量。
6. TypeScript、组件测试、生产构建通过；`mvn test`、`mvn -DskipTests package` 和包含前端的 JAR 构建通过。
7. 文档说明开发双服务与 IDE 单服务启动方式；保留锁定评测数据和后端默认开关。

## 备选方案

React + Vite 为推荐方案，适合现有 Spring Boot API 和本地练习。Next.js 增加服务端渲染/Node 服务，对当前应用收益有限。React + 大型后台组件库能更快搭管理页面，但聊天和餐食界面需要较多定制，因此首版采用自定义组件与 CSS，优先控制依赖和保持可读性。
