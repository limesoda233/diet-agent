## 目标

回答“Jev 本身是否更准、接入回退后是否有收益、延迟与调用量是否增加”。沿用生产识别/修正逻辑，不修改线上路由、prompt、模型接受阈值或主集标注。审查中发现 Jev 用量解析将部分缺失字段默认为零，本阶段同时修正这一元数据问题，不改变意图选择或回退。

## 范围

1. 冻结 84 条主集、原 IntentAgent prompt、Jev criteria、意图修正和固定槽位字典，记录哈希。
2. 16 条补充开发诊断样本独立计分；标注是初稿，不写成双人审核或锁定测试。
3. 对同一输入分别执行原链路、生产 Jev+回退；从后者截取 Jev 原始决策，不额外调用以免抽样不同。
4. 报告意图修正前后、分标签/切片、混淆、配对差异、延迟、决策来源/回退、已知 Token 和置信度诊断。失败在分母，缺失 usage 为 null。
5. 默认一轮，支持三轮及均值/标准差/最差；先连通性检查再全量，不挑选最佳成绩。
6. 评测显式启用后才读取 src/.env 白名单；不执行内容、打印 Key 或读取 DB_PASSWORD；普通测试不联网。
7. 每次输出独立目录、逐样本检查点；服务访问失败立即停止或连续三次失败停止。报告保留未完成状态，不宣称效果提升。
8. Jev 阻断时可单独测 BASELINE，明确不是完整对照。真实评测所需外部服务可用性是执行前提。

## 验收

- 离线证明低分 RAW 保留、真实回退链路预测和 usage 可观测；HTTP 错误不会被正确回退掩盖。
- 统计测试证明失败分母、NO_PREDICTION、主/诊断隔离、配对差异、高分错误及重复波动。
- src/.env 的解析/优先级/白名单/脱敏测试通过，固定数据合法且不覆盖原主集。
- 默认 mvn test 与 mvn -DskipTests package 通过；前端没有变化。
- 提供指南和真实运行状态，服务阻断如实记录。只有完整成功对照才允许讨论 Jev 效果提升。
